# Chrome 扩展费用显示规则

## 本次费用预估

适用模型 `stt-rt-v5`，价格核对日期 2026-09-07。输入音频每百万 token $2；输入文字、输出文字各 $4。按音频每小时约 30,000 token、每字符约 0.3 token 换算。输入字符包括每段重新提交的背景提示和术语 JSON；输出包括日语转写与目标语言译文，临时文本修订替换估计数，不反复累加。字符换算不是供应商 tokenizer，不保证精确。

每段估算 = max(已发送音频秒数, 连接秒数) × 30,000 / 3,600 × 2 / 1,000,000 + (输入字符 + 输出字符) × 0.3 × 4 / 1,000,000。

金额随音频发送约每秒更新。静音但连接仍开启时计入估算；检测到播放器暂停/跳转后断开上游，冻结该段估算。恢复或切换语言建立新段，当前翻译的所有段累加。不能检测暂停事件的嵌入播放器可能继续累计，应手动停止。隐藏原文只改变显示，不减少转写 token。

停止与网络中断会冻结本地估算。服务端尝试正常结束上游，最长等待 5 秒；收尾时间、迟到文字、连接建立时间及真实 token 数与本地计数可能不同。异常关闭或未收到 ready 的请求可能无法完整估算与匹配。其他模型显示预估不可用，不套用 v5 的价格。

## Soniox 已归账

通过 `GET /v1/usage-logs` 查询，每条连接对应 `client_reference_id = kotoba:<随机 UUID>`，仅汇总匹配编号的 `cost_usd`；按日志 UUID 去重，采用十位小数精确求和。界面显示六位小数，金额悬浮提示保留原始精度。

Soniox 日志按请求结束时间查询。请求结束后才可能出现，未公布固定归账延迟；未发现记录显示等待，而不是零费用。失败请求可能无完整日志。界面显示“已归账段数 / 本次总段数”，全部匹配且本次所有连接都结束时才标记“本次记录已齐”。

弹窗打开时自动查询，间隔至少 15 秒；手动刷新受同一间隔限制。查询错误保留上次金额并标记查询失败，不将缺失或失败当零。后端最多翻 10 页、每页 1,000 条；达到上限时报告查询不完整，不展示部分查询的合计。本工具查询窗口限制为最近 30 天。

“本次预估”覆盖全部连接；“已归账”只覆盖已找到的记录。两者不能相加。差额以供应商日志为准；日志成本不等同于含税发票、信用余额扣减或银行卡支付金额，也不包括本机运行、服务器及其他服务成本。

当前只保留本次或最近一次会话的临时元数据。开始下一次会覆盖显示，关闭 Chrome 或重新加载扩展会清除。历史金额请使用 Soniox 控制台。此功能没有向用户收费或扣额度。

另有独立的 [收费内测方案](monetization-v1.md) 与 Stripe 本机测试页面，用于验证购买后的测试额度发放。该测试账本尚未接入本页描述的音频会话，不能将供应商成本显示当作用户额度扣减。
