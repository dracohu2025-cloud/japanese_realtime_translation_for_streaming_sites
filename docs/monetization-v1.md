# Kotoba 收费内测方案

日期：2026-09-07。状态：定价假设已确认；当前只开放本机 Stripe 测试流程，不向真实用户收款。

## 商品与权益

报价来源为 `server/payment-catalog.js`，金额使用美分、额度使用秒。

| 方案 | 价格 USD | 权益 | 到期规则 |
| --- | --- | --- | --- |
| 免费试用 | 0 | 一次性 20 分钟 | 不自动转付费；正式版每个已验证账户限领一次 |
| 月度会员 | 9.99/月 | 每周期 10 小时 | 按 Stripe 实际账单行 period 生效与到期，不结转 |
| 加时包 | 4.99/包 | 5 小时 | 支付确认起 90 天，不自动续费 |

所有方案提供相同的现有字幕功能。每个正式账户最多同时翻译一个音频源；扩展与桌面端共用额度。暂不包含独立声纹模型或语音输出。月费自动续订，取消只影响后续续费，已付周期权益保留；有效加时包不依赖会员是否续订。

## 计时规则（已接入 8791 本机账户内测）

只按服务端接收并交给上游处理的有效 PCM 样本数计量，以整数样本累计，展示时换算秒数，不逐请求向上取整。单声道 16 kHz PCM16 的 32,000 字节为一秒。

连接建立、等待、暂停后无音频输入不计费；播放中的静音计时。用户回放或跳转后重新翻译计时；后台重试应使用同一逻辑音频段标识，不重复扣。隐藏日文原文不改变扣减。不能自动检测暂停的播放器必须支持手动停止，并提示仍在采集。

优先扣月度额度，再扣试用额度，再按到期先后扣加时包。到期按服务端 UTC 时间判断。用量达到上限立即停止接收/转发，不允许负余额，不自动加购。服务器自身失败且无法交付字幕的片段需要退款或补回额度的机制。

## 成本假设

每小时 $0.30 是预算占位，不是供应商固定价或实测账单。用户用满 10 小时，$9.99 收入减 $3.00 可变服务成本后剩 $6.99，约占收入 70%；尚未扣支付费、退款、免费试用、固定开销、获客和人工。每小时成本升至 $0.60 时，余额占比约为 40%。不能将 70% 对外宣传成实测毛利率或净利率。

首轮建议邀请 20–30 位目标用户，记录首次出字幕成功率、试用使用量、付费意愿/实际转化、每周复用、每个付费用户真实成本以及退款原因。采集指标以用量与错误元数据为主，不要求上传字幕或视频内容。

## 当前实现与边界

- 独立本机端口 8790，只接受测试密钥；读取 Stripe CLI 默认 profile 的测试凭据，启动前验证 `livemode === false`。
- 按 lookup key 复用 Kotoba 测试商品与价格，服务端验证金额、币种、周期，浏览器不能传入价格或客户 ID。
- Stripe 托管 Checkout 支持月度订阅与单次加购，银行卡信息不经过 Kotoba。
- 客户端返回页面只触发余额查询；月费由 `invoice.paid` 核实已付账单后发放，加时包由付款成功的 Checkout 事件发放。
- 必须验证原始请求体签名，并从 Stripe 再次读取支付对象，核对测试模式、客户、项目元数据与价格。
- 月度按订阅与账单周期去重，加时包按 Checkout ID 去重，处理不同事件 ID 的重复通知。过期/未来周期额度不计入当前余额。
- 取消测试订阅自动续订，不清除已付权益。
- 本地账本位于被 Git 忽略的 `output/billing-test/ledger.json`，串行事务与原子替换写入；重启保留测试客户及权益。它不是云端多用户数据库。

**8790 仍是共用支付演示。新增 8791 账户内测已支持 Better Auth 邮箱 OTP 测试登录、每账户独立额度、翻译扣时和余额耗尽停止。真实 Google/邮件登录、试用防滥用、云端部署、退款/争议权益调整及正式收款仍未开放。** 两个测试入口都拒绝 live 密钥。详见 [账户与 Cloudflare 方案](accounts-and-cloudflare.md)。

## 本机运行

前提：Node 22+、已安装依赖、`stripe login` 的 default profile 有有效测试凭据。

```sh
npm run billing:test
```

打开 <http://127.0.0.1:8790/pricing>。启动脚本使用 Stripe 官方 SDK 创建/复用测试商品，并启动 CLI Webhook 转发，签名密钥只保留在进程内存中，不输出到终端。停止脚本也会停止该监听。原有 8787 翻译服务不需要停止。

这是本机共用的单一测试账户，不同浏览器看到同一额度。页面可领取试用、跳转测试收银台、刷新到账结果、取消续订。测试收银台使用 Stripe 测试卡，不能使用真实卡。

```sh
npm run check
npm test
```

## 正式收费前的完成条件

1. 使用经过验证的登录身份关联 Stripe Customer，额度与会话均在服务端授权，替换本机配对模式。
2. 事务数据库：支付事件、账单、额度批次、音频用量、退款调整；并发扣减原子化；失败重试及事件乱序可重放。
3. 翻译链路接入计时和断流，实测暂停、跳转、断网、并发设备、余额边界。
4. 完成支付失败、取消、退款、争议、税费、退款政策及账单查询。接入明确的账户管理入口。
5. 确认收款主体、实际业务可接入性、用户条款、适用税项及正式域名。测试账户可用不代表 live 业务审核通过。
6. 对日语样本实测效果、延迟和成本；在实际完成上述能力后再邀请用户付费。

来源：[Stripe Checkout](https://docs.stripe.com/payments/checkout/build-subscriptions)、[订阅 Webhook](https://docs.stripe.com/billing/subscriptions/webhooks)、[回调验签](https://docs.stripe.com/webhooks/signature)、[Soniox 定价](https://soniox.com/pricing)。

## 首轮支付验证（8790）

- `npm run check`、`npm test`：32 项测试通过，其中 9 项覆盖支付验签、重复通知/周期幂等、错误客户/价格/金额、到期、取消续订、服务端价格锁定、Stripe 查询失败重试及 HTTP 授权。
- 使用 DracoNova Inc 的 Stripe 测试模式，通过浏览器提交月度 $9.99 与加时包 $4.99 的测试卡付款；实际 Webhook 发放 36,000 秒与 18,000 秒。
- 加上一次性试用 1,200 秒，页面与本机账本总额为 55,200 秒（15 小时 20 分钟）。服务重启后数据保留。
- 浏览器取消测试订阅自动续订成功，`cancel_at_period_end` 为 true，已有额度保留。
- 本轮没有真实扣款，也没有实测续订扣款、退款或实际翻译扣额度。续订周期去重与未来周期生效由自动化测试验证。
- `npm audit --omit=dev` 无已知生产依赖漏洞；完整依赖审计仍报告原有桌面开发/打包依赖的问题，未做破坏性依赖升级。

## 账户与扣时增量验证（8791）

- 新增账户验证码、错误尝试、退出撤销、Stripe 客户路由、用户隔离、采样计量、并发会话和余额边界集成测试。音频边界自动化使用本机假上游，不代表日语识别效果测试。
