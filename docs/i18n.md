# 界面语言

用户网页（云端 `/`、`/pricing`）、Chrome 插件弹窗/设置/字幕工具栏，以及验证码邮件支持简体中文与英文。旧的本机开发控制台和 Electron 桌面实验端不属于本次用户界面范围。

- 初始选择为“跟随浏览器”。网页按照浏览器语言偏好匹配中文或英文，插件使用 Chrome 的界面语言。不支持的语言回退英文，中文地区变体目前统一显示简体中文。
- 网页与插件各有“界面语言”选择器。网页用 `localStorage`，插件用 `chrome.storage.local` 记住选择；各自页面间同步，不跨账户、跨设备同步。
- 手动切换只重绘产品文案，不刷新网页、不重新登录、不清空输入和连接码，也不重新开始音频采集。字幕目标语言是独立的 `targetLanguage` 设置。
- 时间、数量、日期、百分比使用 `Intl`。金额始终是 USD，不进行汇率转换。日期按使用设备的本地时区显示。会员单复数由时长格式化器处理。
- 验证码请求携带所选界面语言的 `Accept-Language`。服务端映射到两个允许的语言，通过请求隔离的上下文传入邮件模板；未指定或无法匹配时回退英文。切换语言不改变验证码的有效期、限频或验证规则。已发送邮件不会因随后切换语言而改变。
- 安装名称、说明、工具栏提示使用 Chrome 原生 `_locales`；这些浏览器管理的文字跟随 Chrome 语言，页内选择不会修改它们。

## 维护约定

共享资源位于 `extension/shared/messages.js`，以中文源文作为消息键（类似 gettext），英文提供完整对应译文。调整源文时同步修改键与所有引用。动态文案使用 `{name}` 命名参数，避免拼接句子。

`i18n-core.js` 提供纯格式化与翻译能力，`i18n.js` 是模块入口。`ui-locale.js` 在页面初始化时绑定静态文字；动态内容使用 `bindText(element, () => ...)`，回调在切换语言时重新计算。只绑定产品文案，用户的字幕、输入、邮箱和连接码不进入翻译流程。资源不含 HTML，页面通过文本节点写入译文。

内容脚本通过扩展注入同一份资源，收到 `uiLocale` 后更新工具栏；不需要扩大网站读取权限或暴露资源给网页。网页构建仅复制四个共享脚本到静态目录。验证码模板也复用这些资源。

后端业务错误使用稳定 `code`，客户端映射到本地文案；未知错误显示通用提示，不直接显示供应商响应。开发日志与服务端内部错误无需翻译。

## 验证

运行 `npm test`、`npm run check`、`npm run cloud:assets`、`npm run cloud:test` 与 `npm run package`。检查资源参数一致性、静态文案覆盖、语言回退、美元不变、并发邮件语言隔离、连接码重建校验和字幕不被界面切换改变。

浏览器检查需覆盖：未连接/已连接/连接码过期、中文/英文、切换时保留表单、账户余额与到期日期、390px 插件窗口与 330px 高度滚动，以及网页窄屏。
